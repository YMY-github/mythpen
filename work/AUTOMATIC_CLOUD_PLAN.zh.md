# 自动云文档改造（用户已确认轮流使用）

目标：连接 Google 后所有作品自动同步；一个字的已保存修改也上传；另一台启动/打开作品时先自动取云端最新稿。普通设置仅显示连接与自动同步状态，不暴露版本、冲突选择、保留数量或手动更新。

语义：云端新稿优先；本机只有待上传修改且云端未变时自动上传。两边都变时自动采用云端，本机已保存稿先留隐藏恢复副本。不是同时逐字合并；用户已明确主要轮流使用。断网允许继续本机写作并自动重试。

实现：保留旧不可变快照兼容；新增自动文档服务、缓存已验证的远端摘要、自动发现导入、打开前同步门禁、前台轮询和短延迟自动保存上传。上传与应用不能并发破坏稿件；应用必须校验本机哈希和编辑状态，取消请求不得之后再替换编辑中的作品。

验证：单字、空稿、远端更新自动应用、双端修改云端优先及恢复副本、上传期间编辑、断网重启、首次安装自动发现、同名不同作品隔离、请求取消与旧哈希保护；再跑完整类型检查、编译服务、真实合成 Drive 往返与 Windows 安装 CI。

当前：已检查保存链路；原编辑器默认 30 秒本机保存，会改为约 0.5 秒并补连续输入、中文输入法、切章/关闭及异步保存竞态保护。现有应用与真实用户作品不用于开发测试。

## 实现与验证更新

已实现自动云文档服务、云端优先恢复、自动发现导入、打开前同步门禁、短延迟自动保存、大纲/标题草稿队列和简化设置。云端按设备维护当前文件并 PATCH 更新；旧历史不删，普通界面不显示版本管理。

78 项核心/HTTP/协议测试和 8 项内存 DOM 集成测试通过，TypeScript 与网页构建通过。真实 Google 两进程自动往返、双端修改后的云端优先及本机恢复点、当前文件数不随修改增长均通过；约 10 MB 的单字修改可恢复 PATCH 更新同一个文件并取回一致。没有读取/改写用户真实作品，也未删除云端文件。

下一步：发布开发分支并执行 Windows 安装/冷启动 CI；新建 Mac ARM 安装镜像，核对校验值。新版可见界面及真实 Windows/双实体设备验收仍有独立边界，不能用内存 DOM 或同机两进程代替。现有已安装应用尚未替换。
