# 自动云文档规则（0.0.10）

用户确认的使用方式是：主要在 Mac 和 Windows 之间轮流写作。Google 云端保存当前稿，修改后自动上传，另一台电脑打开时自动下载；不需要选择版本或手动更新。

## 日常使用

连接 Google 后，作品自动参与同步。另一台使用同一个桌面 OAuth 配置、独立登录同一个 Google 账号，会自动发现并导入云端作品；身份按作品 ID 区分，同名不同作品不会合并。

正文、标题和大纲输入后约半秒保存到本机，随后排队上传；一个字、空格、空稿和删除正文同样属于修改，没有最小字数门槛。连续输入会合并短时间内的请求。实际上传用时取决于网络与作品大小，不能把本机保存成功当成云端成功。

打开作品时先检查并协调云端状态，再显示可编辑正文；前台约每 3 秒检查当前作品，回到前台或恢复联网也会自动检查。后台保存触发上传，周期检查用于重试。普通界面只显示本机保存、正在同步、已同步和需要处理的连接错误；不再提供版本选择、同步开关、手动下载或历史清理。

## 云端优先与离线

- 云端未变、本机有修改：自动上传。
- 云端已更新：自动下载应用，不要求确认版本。
- 两台都改过：采用云端新稿，本机已保存稿先留恢复副本。按 Google 的更新时间选择当前稿，不依赖两台设备的本地时钟。
- 断网：允许使用本机稿继续写；恢复网络后自动协调。未上传的修改只有完成上传后，另一台才能获取。
- 无法连接 Google 或未配置：仍可在本机写作；界面显示本机保存或等待同步，不假报云端成功。

这是自动轮流编辑模式，不是两个人同时逐字合并的协作编辑器。换设备前看一眼“已同步至 Google”即可，不需点击保存或更新。

## 存储与安全

同一部作品在界面中只有一个项目；云端内部每台设备维护一份当前稿文件，通过 Drive PATCH 更新，避免每次改字增加一个完整历史文件。分开的设备记录保留并发上传的内容，最新稿按 Google 文件时间协调。旧预览的历史文件不会被自动删除，后台替换前的本地恢复副本也会保留。恢复工具属于内部兼容/维护接口，不出现在日常设置中。

同步包含作品数据库和封面，排除全局设置、AI 密钥、Google Token 及客户端配置。Token 使用系统凭证存储，不采用明文回退；权限仍为 drive.appdata。作品使用 HTTPS 传输，没有端到端加密。

每次上传取回验证大小、身份与 SHA-256；自动应用前校验数据库与当前本机哈希，并确认无写入或 AI 任务。编辑草稿先写入本机持久化队列，异步旧响应不能清掉新输入；中文输入法组词完成后再上传。打开请求取消或超时后，后端不得稍后再替换已恢复编辑的稿件。

当前仍传输完整快照，原始作品文件合计上限 64 MiB。超过 5 MiB 的 JSON 使用可恢复上传，8 MiB 分块；支持已有当前稿文件的大文件 PATCH 更新。已验证的历史摘要可缓存，最多处理 10000 个远端文件；不是差量同步。旧历史和恢复副本可能占用空间，不进行无人值守永久清理。

Mac 和 Windows 均需更新到 0.0.10 才具有这套自动界面。旧版仍按旧交互工作。设备各自建立身份，不要把整个应用数据目录或登录 Token 复制成另一台的身份。

协议参考：[Google 文件更新](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/update)、[上传与恢复](https://developers.google.com/workspace/drive/api/guides/manage-uploads)。
